The data we are using is a panel data containing various financial features a US company has and whether it went bankrupt between 1998-2018 originate from [reference]. Since our goal is to train the algorithm to be able to classifie a company that is potentially about to go bankrupt, there are several data processing rask that we need to do before it is usable.

Firstly, one of our aim is the examine whether that lag features(Information from previous years) can help predict the potential bankruptcy in current year. In this project, we considered up to 3 lag years. In order to do so, the data from year 1998 - 2001 is removed as some of the lag features they contain will have NAN values and we believe that they tradeoff between removing instead of imputing missing value is justified here given that the data set is quite large. Additionally we also need to remove company which contains less than three consequtive recorded years as this results again in NAN values for lag features. It is worth noting that this may introduce a form of bias against younger company. As the data now only consider a stable company with age of atleast 3 years.

Secondly, the dataset labeled healthy companies between 1998-2018 as ‘alive’ and companies that has gone bankrupt during this period as ‘bankrupt’ for all years instead of only on their final year. This means that if we were to train the algorithm using financial feature from many years before a company bankruptcies, when the company might still be healthy, the algorithm might learn characteristic of a perfectly healthy company as potential indicator of bankruptcies. This may shift the decision boundary in an unwanted ways. To avoid this, we change all bankrupt labeled to ‘alive’ except for the final year. Additionally, this also avoid a variant of a phenomenon referred to as temporal leakage, where for example if the company went bankruptcies during year 2018 and say we decided to train the data up to a certain year before 2018 then we should not have access to this information in the training set.

Finally, we need to address the issue of cross sectional leakage. This phenomenon occurs when the same companies appear in both train and test dataset. It results in implicit structure of a company being learned within the training set. For example if the underlying true model of the financial features is a variation of a fixed effect model, the algorithm may implicitly learned these features and inturn do a better job at predicting the behaviour of these companies. Although this provide no issue if the goal is to forecast the behaviour of these companies. However, the aim of this project is to generalised the algorithm to be able to predict the bankruptcies of unseen companies and so these form of leakage is undesirable.

Both temporal and cross sectional leakage introduced their own unique issue that leads to an overestimation of the performance of the trained model in the test data. This may results in potential investor or users of the algorithm having a skewed perception of the algorithm reliability. Therefore it is critical that we address these issue pressing forward. In order to do so, we followed the guideline on how to split the data from (reference) closely. Additionally, for method that required standardization, special care is given to avoid temporal leakage. How these procedure is achieve will be describe throughout this R-markdown file.

Now that the data has been pre processed, it can now be split in to a train and test set. Given the three dimensional structure the panel data possessed, a traditional method will introduce an overestimation of the performance here, Limiting the model ability to generalise to real setting. This is due the effect of temporal and cross sectional leakage as discussed earlier. Taking this into account, we choose to split the data into a four segments. First we split the data company wise into a train and test set following a \(80%/20%\) train test split. We then split again timewise, where we only consider the year 1998 to 2013 for training set, and \(2014\) to \(2018\) for test sets. This prevents the effect of temporal leakage where if the data is trained on the future time and information it may better learn autocorrelation structure and overestimate a performance onto a generalised model. Additionally, it is ideal that the test data accurately reflects real use. In this sense future knowledge is not accessible and so train and test should reflects accordingly.

Additionally, in this half of the process we will perform signed log transformation and and creates a standaised version of the data. The signed log transform is done to reduce the effects of the outlier values. Here we chose not to remove them as they may represents, companies which out performs your average companies. Hence, removing them may reduce the effectiveness of the performance of the algorithm to predict behaviour of companies with those characteristics.

Meanwhile, The standardisation is a crucial step in ensuring that the algorithm which use distance metric is not contaminated by the differing feature scales as features with larger scale will dominates the computation of euclidean distance. Note that given that our data is a timeseries, standardisation cannot be done simply by the standard formula

\[X_{i,j}* = \frac{X_{i,j} - \mu_j}{\sigma_j},\] where \(i\) is the sample index and \(j\) is thre \(j^th\) feature to be scaled This will be discussed further into the markdown file.

Now that we have a signed log transformed data, the next step is is to standardize the data. Before doing so first we need to address the temporal leakage issure. First note if we were to simply compute the mean \(\mu_j\) and the standard deviation \(\sigma_j\) then standardise the data using these time global values then the train data will be rescaled based on the \(\mu_j\) and \(\sigma_j\) which was computed using future values. Again, in real context future information should not be allow and this is another case of temporal leakage. An alternative method is to simply compute the mean of the train data and the apply the scaling parameter across the whole set given by \[X_{i,j}^* = \frac{X_{i,j} - \mu_{j,train}}{\sigma_{j,train}},\] where \(\mu_{j,train}\) and \(\sigma_{j,train}\) are mean and standard deviation of the \(j^{th}\) feature obtained using the train data set.

However, this method of standardisation failed to account for the effect of time drift (the parameters may shift with time) as shown here

From the graph we can see clearly that the time drift in the data is quite significant. Given the limited understanding and lack of access to expert knowledge which may be available in a real world setting our best guest is to account for this drift by adjusting for inflation. Since the data concerns US company, we attempt the adjust by using USA mean CPI index for each year. This data is obtained from https://fred.stlouisfed.org/series/CPIAUCSL. The inflation is adjusted by using the formula

\[X_{t,adjust} = X_{t} \times \frac{CPI_{2002}}{CPI_{t}}\] here the year \(2002\) is used as the base year since after preprocessing (removing the first 3 years of the data to remove the NAN from lag features.)

library(dplyr)

df_adj <- df %>%
  left_join(inflation, by = "year") %>%
  mutate(across(7:23, ~ .x * (cpi_base / cpi)))
